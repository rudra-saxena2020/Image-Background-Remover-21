Official BiRefNet repository:

https://github.com/ZhengPeng7/BiRefNet.git

This tool is specifically designed for **e-commerce product images**, including:

Clothing
Shoes
Bags
Accessories
Furniture
Electronics
Beauty products
Home products
Packaged goods
General catalogue products

The priority order is:

**1. Fast processing**
**2. Clean product edges**
**3. Accurate product preservation**
**4. Original-resolution output**
**5. Ability to process many product images efficiently**

The application must actually run BiRefNet inference. Do not build a fake/demo background remover.

# Core Workflow

User opens dashboard

→ Upload product image
→ Show product preview
→ Click Remove Background
→ Send image to backend
→ BiRefNet processes product
→ Generate foreground mask
→ Remove background
→ Return transparent product PNG
→ Show result immediately
→ Download PNG

Target the shortest possible time from upload to visible result.

# 2. Product-Specific Processing

Optimise the pipeline specifically for isolated product photography.

The model should preserve:

Product shape
Thin edges
Shoe laces
Bag straps
Handles
Jewellery
Clothing edges
Hair-like fibres/fur on products
Transparent-looking product boundaries where possible
Small product details

Do NOT crop parts of the product.

Do NOT remove white parts of a product simply because the original background is white.

Do NOT confuse shadows with product edges.

Avoid:

White halos
Black halos
Jagged edges
Over-smoothed boundaries
Missing product sections
Background fragments

The output must contain the complete product on a transparent background.

# 3. SPEED IS CRITICAL

Design the backend for extremely fast repeated processing.

BiRefNet MUST load once when the backend starts.

Never reload the model for each request.

Keep:

Model loaded in memory
Model loaded on GPU when available
CUDA context warm
Required inference resources ready

Use:

torch.inference_mode()

Use FP16 on supported CUDA GPUs.

Use modern PyTorch optimisations supported by the BiRefNet implementation.

Consider torch.compile only when benchmarking proves that it improves the actual deployment environment without causing instability or excessive startup cost.

Warm up the model during application startup with a dummy inference so the first real product does not pay the full cold-start penalty.

Never call:

torch.cuda.empty_cache()

after every image unless there is an actual memory-pressure reason. Constantly clearing the CUDA cache can hurt throughput.

Reuse GPU memory efficiently.

Avoid unnecessary:

Disk writes
Image copies
PNG encode/decode cycles
CPU ↔ GPU transfers
Model initialisation
Temporary files

Where possible:

Upload
→ decode in memory
→ preprocess
→ GPU
→ inference
→ mask
→ composite
→ encode PNG
→ response

Keep the hot path in memory.

# 4. Fast Mode vs Quality Mode

Provide two processing modes.

## Fast

Default mode for normal product catalogue images.

Prioritise speed while maintaining strong product segmentation.

Use an appropriate lower inference resolution while preserving the original image for final compositing.

The generated mask can be resized back to the original image dimensions.

## High Quality

Designed for:

Jewellery
Complex clothing
Thin straps
Hair/fur
Complex edges
High-resolution catalogue images

Use a higher-quality BiRefNet configuration/model.

High Quality can be slower.

The default must be:

**Fast**

# 5. Dynamic Resolution

Do not process every product at maximum resolution.

That wastes GPU time.

Determine an appropriate inference resolution based on:

Image dimensions
Selected quality mode
Available GPU memory
Model requirements

Preserve the original uploaded image separately.

Run segmentation at the selected inference resolution.

Then resize/refine the resulting mask and apply it to the original-resolution product image.

Final output:

Original width × Original height

Transparent PNG.

Do not upscale the source image.

# 7. Fast API Behaviour

Optimise FastAPI for binary image handling.

Do not convert uploaded images to Base64.

Use multipart binary uploads.

Return binary PNG or WebP responses directly.

Avoid saving images to disk unless required.

Use BytesIO or equivalent in-memory processing.

Configure sensible upload limits.

Handle:

Invalid images
Unsupported formats
Corrupted uploads
GPU OOM
Inference errors

Do not expose internal stack traces.

# 8. GPU Concurrency

Do NOT blindly process unlimited simultaneous GPU requests.

Implement an inference queue or semaphore.

Example concept:

Upload requests
↓
FastAPI
↓
Inference Queue
↓
BiRefNet GPU Worker
↓
Results

Configure concurrency based on available VRAM.

For a single GPU, start conservatively and benchmark.

The goal is maximum throughput without causing CUDA OOM.

CPU preprocessing can happen concurrently where appropriate.
