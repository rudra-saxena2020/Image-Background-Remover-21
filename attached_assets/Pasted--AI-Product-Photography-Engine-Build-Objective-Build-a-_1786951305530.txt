# AI Product Photography Engine

## Build Objective

Build a production-ready AI SaaS inside Replit that converts uploaded e-commerce product images into professional, high-quality fashion/product photography.

The application must support products such as:

* Handbags
* Tote bags
* Shoulder bags
* Crossbody bags
* Backpacks
* Wallets
* Watches
* Jewelry
* Shoes
* Sneakers
* Clothing
* Sunglasses
* Belts
* Perfumes
* Beauty products
* Accessories
* Other physical products

The most important requirement is:

**Use the user's uploaded product images as the actual source product. Do not hallucinate or recreate the product from text.**

The system should generate 6 to 8 different professional images per product while preserving the exact product identity.

---

# 1. MODEL STRATEGY

Do not hard-code a single image model.

Create a model abstraction layer:

```text
ImageGenerationProvider
    |
    +-- Qwen Image Edit 2511
    |
    +-- FLUX Schnell
    |
    +-- Optional future models
```

### Primary model

Use:

**Qwen-Image-Edit-2511**

Use it primarily for:

* Product-preserving image editing
* Product + human composition
* New viewpoints
* Lifestyle scenes
* Character consistency
* Image-to-image generation

Qwen-Image-Edit-2511 is specifically an image-to-image editing model and its current model documentation highlights improved character consistency and reduced image drift. It is released under Apache 2.0.

### Fast fallback

Use:

**FLUX.1 Schnell**

Use it when:

* Qwen is unavailable
* Qwen generation fails
* Fast preview generation is requested
* User selects Fast mode

FLUX.1 Schnell is an open-weight model under Apache 2.0 and is designed for high-quality generation in only 1 to 4 steps.

Do NOT use FLUX.1 Dev for the default commercial pipeline because its current model documentation lists a non-commercial license.

---

# 2. IMPORTANT: FREE DOES NOT MEAN FREE GPU

The models themselves are open-weight/free to use under their respective licenses.

However, GPU compute is still required.

The application must detect whether CUDA is available.

If CUDA is unavailable:

```text
STATUS:
GPU unavailable
```

Do not pretend local generation is working.

Do not silently fall back to CPU for large image generation.

Instead provide:

```text
GPU Required

Choose:
[Connect GPU]
[Hosted GPU]
[Configure Provider]
```

The architecture must support a remote GPU worker later.

Provide three modes.

## FAST

Optimized for speed.

Use:

## QUALITY

Use Qwen-Image-Edit-2511.

Purpose:

Priority:

# 5. MULTI-REFERENCE PRODUCT ANALYSIS

Before generation, analyze every uploaded image.

Create an internal Product Identity Profile.

Example:

```json
{
  "category": "womens_handbag",
  "gender": "female",
  "material": "woven_leather",
  "primary_color": "dark_burgundy",
  "hardware": "gold",
  "shape": "large_tote",
  "handles": 2,
  "strap": true,
  "pattern": "woven",
  "logo": true
}
```

Never expose unnecessary internal analysis to the user.

Use all uploaded references together.

Do not treat them as separate products.

---

# 6. SOURCE IMAGE LOCK

This is the highest-priority rule.

The uploaded product images are the source of truth.

The generation request MUST include the source product image(s) as image inputs.

Do not send only a text prompt.

Do not recreate the product from a text description.

Do not generate a generic replacement product.

Do not approximate the product.

The source image must be used for image-to-image/editing conditioning.

# 10. HUMAN MODEL RULE

If `model_required = true`:

A human MUST appear in the final image.

The image is invalid without the human.

Never silently return a product-only image.

Never use a mannequin.

Never use a generic flat cutout model.

Never use a pasted human.

The model must look like a real adult fashion/commercial model.

---

# 23. BACKGROUND REMOVAL

Pipeline:

```text
Generated Image
       ↓
Foreground Segmentation
       ↓
Mask Refinement
       ↓
Hair/Finger/Strap Edge Refinement
       ↓
Alpha Matte
       ↓
Transparent PNG
```

Use BiRefNet or another high-quality segmentation model.

Do not remove important foreground elements.

Preserve:

* Hair
* Fingers
* Thin straps
* Jewelry
* Shoe laces
* Product edges

# 26. PERFORMANCE

Optimize for fast generation.

Use:

* FP16/BF16 where supported
* Model caching
* Persistent model loading
* GPU memory management
* Batch processing where safe
* Concurrent jobs
* Queue system
* Reusable model instances
* Avoid loading the model for every image

Do not initialize the model separately for every request.

Load it once per worker.

Do not consider the application complete until this test passes.

Upload the provided handbag references.

The system must produce:

```text
01 Product-only handbag
02 Female model holding handbag
03 SAME female model, different angle
04 Close-up handbag detail
05 Different handbag angle
06 SAME female model walking with handbag
07 Close-up craftsmanship
08 SAME female model editorial hero
```

Images 2, 3, 6 and 8 MUST contain a real human model.

The handbag must be the exact uploaded handbag.

The model must not be reused from another product.

The model must not change identity between frames.

Hands and face must pass quality validation.

The final PNG must have a genuine transparent background.

If the system produces eight product-only images, the implementation is considered FAILED.

If the system produces a generic mannequin, the implementation is considered FAILED.

If the system changes the handbag design, the implementation is considered FAILED.

If the system returns a white background instead of alpha transparency, the implementation is considered FAILED.

# FINAL ENGINEERING PRINCIPLE

Do not optimize for "generating an image."

Optimize for:

**SOURCE PRODUCT PRESERVATION + CATEGORY-AWARE HUMAN GENERATION + REALISTIC PRODUCT INTERACTION + CONSISTENT MODEL + TRANSPARENT OUTPUT + AUTOMATIC QUALITY CONTROL.**

The system should behave like an automated luxury product photographer, not like a generic text-to-image generator.
